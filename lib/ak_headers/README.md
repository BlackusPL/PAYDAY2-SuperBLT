# WWise Apache-licenced header files

Surprisingly, a lot of the files from the WWise SDK are dual-licenced with a commerical licence
and the Apache-2 licence. It turns out that this is because AudioKinetic wants to make it possible to
write WWise plugins without licence terms getting in the way.

They've got an old copy of the headers on GitHub [1] but they're about 10 years old. Searching GitHub
for AkPlatforms.h finds a few public projects that contain a copy of the SDK. From here you can remove
all the non-Apache-licenced files to get a clean copy we can redistribute.

The verify_licence script reads the headers of all the includes to make sure no proprietary files
slipped through the cracks.

[1] https://github.com/audiokinetic/WwiseIncludes

## Binding system

The EXE exports the symbols, which we can load at runtime with GetProcAddress. These function pointers go
into a big struct named WWISE_FUNCTION_TABLE. We auto-generate bodies for the functions declared in the
wwise headers, and these functions then call the function pointers stored in that struct.

This is all inside the `wwise_bindings.gen.cpp` file, which is auto-generated from the `generate_bindings.py`
script to include all the functions imported by `generate_binding_targets.h`.

The script uses libclang's python bindings, which can be installed with the `libclang` pip/pypi package. While
I dislike it on principle, the generated file is committed to avoid making this a build-time dependency.

You can run the script like so:

```powershell
py .\generate_bindings.py --out wwise_bindings.gen.cpp
```

There's a couple of functions that aren't exported by the EXE for whatever reason, so `exe_exports.json` contains
a list of all the symbols the EXE does export, as generated by:

```powershell
py .\generate_bindings.py --out wwise_bindings.gen.cpp --exe '<path>\PAYDAY2.exe' --update-exports-json
```

The script then excludes any functions missing from this JSON.
